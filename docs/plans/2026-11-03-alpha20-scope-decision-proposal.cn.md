# 测量后的 alpha.20 范围决定提案

状态：用户于2026-11-03明确接受。[已接受决定](../adr/2026-11-03-alpha20-experimental-closeout.cn.md)及当前逐项清单取代提案状态，下文保留为决定历史。D20-08/Epic163 保持
IN_PROGRESS。2026-11-03已向用户询问范围，同时继续独立的 CI/包验证/交接工作。
这不是发布申请。

[既有方向 ADR](../adr/2026-10-19-alpha20-data-workflow-focus.md)明确要求：NCP 相比
等价 HTTP 未显示额外测量价值时，广泛移植前须作明确设计/范围决定。D04 成对测试
中，原生参考路径的耗时、CPU、分配和 TLS 字节均劣于匹配的 HTTPgzip。D05 普通
工具与 NPS 工具均80/80精确正确，未证明 NPS 独占的模型费用/token/延迟优势。
负面结果是有效证据，不能据此悄悄取消旧30%CGN/50%线路压缩门槛。

## 建议：有边界的实验候选

保留六 SDK 共享解析/错误契约及原有回归验证。只声明[当前支持清单](../qualification/2026-11-03-alpha20-support-ledger.json)
中的实验路径：.NET/Python 结果 HTTP 客户端到 .NET 参考服务端；.NET 宿主绑定的
NIP结果准入；显式启用的 .NET NCP 批次参考；本地 NOP角色及易失 NDP双节点路由。
未实现的 SDK/绑定、完整生产和 governed-challenge profile 继续不支持/未验收，
不自动宣告特性。

采用较窄范围作为发布依据前，原决策方须在既有任务逐项记录：

| 义务 | 所需决定 |
|---|---|
| A20-G01/G07；P20-001..009/401..409（#132） | 绑定清单及具体负责人，批准排除或后续采用，保持独立/归档生命周期 |
| A20-G02/G04；P20-101..109（#129） | 冻结已声明契约/语料，未完成的生产/运行时/challenge语料明确保留后续义务 |
| A20-G03/G05/G08；P20-201..208（#130） | 明确特性/SDK/绑定和公开错误契约，保留旧兼容要求，重新冻结必测单元；历史576项未执行记录保留 |
| A20-G06；P20-301..306（#131） | daemon/bridge清单真实，不宣告未支持特性，后续集成仍未验收 |
| A20-G09；P20-501..509（#133） | 明确故障/传输/观察期适用范围与证据，不用编解码冒充运行时，不虚构观察期 |
| 旧30%CGN/50%线路门槛 | 原决策方明确保留或修改并定义基线；建议采用测量/正确性证据，取消普遍节省承诺 |
| A20-G10/G11/G12；P20-601..607（#134） | 保留安全/权限/签名/源码/版本/漂移要求，范围接受后再生成一致候选；发布与beta单独决定 |

未执行或失败单元不能改成通过。后续义务保留原ID及负责人，须记录适配或延期，
不能删除，也不能擅自移除有约束的采用方。新范围矩阵冻结后仍须执行其必需运行时
单元，实验收口不代表现有结果直接满足所有验收。

另一条路线是 alpha.20 保留原完整六SDK、原生+HTTP生产契约、采用方及验收范围，
继续在既有任务完成缺失实现/证据，并就 NCP负面测量作符合 ADR的明确范围决定。
当前局部绿色测试不能满足该路线。两条路线都不授权发布，也不豁免安全或beta门槛。
