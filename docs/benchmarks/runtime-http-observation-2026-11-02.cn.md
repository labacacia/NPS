# HTTP 运行时配对观察

a4d80af 的 720 次正式工作流（另有 72 次预热）全部通过精确答案、相同模型证据和明确
内存预算检查。这验证测量执行，不代表整个 suite/profile 合格。普通 HTTPS 比当前 NPS
双跳 HTTP prototype 更快、字节更少；没有据此证明原生 NCP 或协议专属 token/内存收益。

依据：[原始观察](runs/2026-11-02-runtime-http-qualified.json)、
[分布](runs/2026-11-02-runtime-http-summary.json)、
[测量边界](runtime-comparison-method-2026-11-02.cn.md)。

环境为 Release .NET 10.0.14、Ubuntu 26.04.1 x64，四 CPU affinity；320MiB managed
heap，进程 RSS 门槛仍为 512MiB。三个规模共享相同不可变来源/存储运算，执行实时 CA/
来源/模型出站授权与实际 mTLS。C/D 模型文本逐字节相同且小于 32768 字节；本实验不调用模型。

前端 warm、响应 gzip 子集（每组 30 次，请求不压缩）：

| 行数 | 路径 | Median / p95 毫秒 | Median TCP/TLS 字节流字节 |
| --- | --- | --- | --- |
| 100 | 普通 HTTPS | 7.88 / 10.45 | 6724 |
| 100 | NPS 网关 HTTP | 80.51 / 83.28 | 75959.5 |
| 1000 | 普通 HTTPS | 13.99 / 16.24 | 7562 |
| 1000 | NPS 网关 HTTP | 75.07 / 82.56 | 77622 |
| 100000 | 普通 HTTPS | 421.76 / 447.51 | 7578.5 |
| 100000 | NPS 网关 HTTP | 499.32 / 513.00 | 77679 |

所有连接/压缩组合和逐次数据均保留，并非只选有利结果。10 万行进程峰值为 468.58MiB，
不能归因成某协议独立分配。字节计入双向 TLS record 与 HTTP framing；NPS 汇总公开/
网关出站。两者均不计 TCP/IP 包开销及单列的共享溯源准备/最终清理。当前网关每次操作
新建下游连接，发现、额外握手/投影/策略都是真实计入的成本；不泛化到所有 NPS 部署。

此前失败全部保留：默认 GC 峰值 1462.07MiB；256MiB 堆尝试创建结果被拒，但未采集确切
错误码；来源缓存/384MiB 和逐行/384MiB 两轮峰值分别 544.16、537.17MiB。原始证据与
通过的部署配置并列保留，不能从这些同时变化的代码/来源/配置中单独推导因果效果。

范围决定：结果生命周期、溯源、授权继续保持 experimental 语义，不宣称小型工具 HTTP
线传输收益。普通工具在模型外计算也能实现相同上下文缩减。NCP 重复 schema、batch、
delta 的价值须由 D20-04 独立传输对照及恰当基线验证；本轮明确不声称原生 NCP、Arrow/
Flight/Protobuf 优势。schema/更新矩阵、共享不变量、安全/发布门槛仍待完成。
有界模型证据回放另行测量，也不等于 D20-05 的在线工具 demo。
