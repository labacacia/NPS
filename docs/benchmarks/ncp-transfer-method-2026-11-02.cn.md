# schema批次传输对照预登记

2026-11-02，D20-04 #168；正式执行前提交。本实验测量模型上下文之外的完整数据传输，
不等于前面的HTTP聚合流程或模型计费，不预设协议胜出、节省比例或资源收益。

使用D20-01 seed-20261102订单/退款值，规模100/1000/100000。各路返回全部字段/行，顺序和
精确分金额相同。传输schema对已知有界金额用int32，其余id/period/reason/refunded用字符串/
字符串/字符串/bool；不冒称旧结果存储的int64 schema hash。独立oracle检查所有ID/值/总和/
计数及最终schema。

六种表示：普通HTTPS JSON对象行(identity/gzip)、普通HTTPS通用MessagePack对象行
(identity/gzip)、已选择native NCP元组流(JSON/MessagePack)。HTTP含同一完整schema及行，
NCP含Anchor、全部Stream、请求/准入及反向credit。MessagePack使用既有库，不宣称
Arrow/Flight/Protobuf；不虚构native gzip，不只比较裸JSON长度。两端使用同一合成来源、
独立pin的mTLS、关闭TLS恢复及当前宿主权限。native用公共会话/发布/读取API，通过现有
应用自有只读ActionFrame触发每次快照；HTTP执行等价已知夹具读命令。请求成本均计入。
不重新定义Nop/Caps或增加协议动作，也不证明其他SDK/通用NIP/PKI/NWP结果订阅。

矩阵为3规模×6表示×冷/暖连接×稳定/变schema任务，共72条件。稳定传一个快照；变更先传
原快照，再传新增nullable note列的完整新快照，旧状态不变，验证新epoch/schema及完整来源
一致性。这里测完整重同步，不宣称实时变更/差量更优；差量正确性另有证据，未与等价选择性
更新基线比较前不公告差量节省。

每条件独立测试进程，3次预热丢弃、30次测量。冷路径每次新建/关闭前端，含TCP/TLS/native
前导/Hello/Caps；暖路径复用连接/准入，所有路线的setup均在计时外。来源生成、证书、服务
启动不计时；实际编码/压缩、对象转元组、严格schema hash、请求/响应/控制I/O、解码/留存和
冷关闭均计时。每阶段执行oracle。变更数据准备在各路计时外，完整新schema传输在计时内。

逐次记录wall、共宿主进程CPU增量、总托管分配增量及计数开销，涵盖客户端/服务端/TLS/GC/
序列化，不能归因某协议子系统。TLS下字节计双向握手/HTTP头/NCP帧及credit，不含TCP/IP。
记录每独立条件进程树峰值RSS，区别逻辑留存字节；不强制GC或清空池缓存。保留全部样本、
median/p95、字节/分配/峰值元数据。正式配置4逻辑CPU、320MiB托管预算、512MiB进程树RSS、
每工作流120秒。失败/超时/OOM/缺样本保留为失败或未知，不删除以制造优势。无供应商调用，
不捏造模型可见量或usage。

方法/捕获代码提交后才跑正式矩阵，记录精确版本/方法/oracle hash、OS/runtime/配置及实际
测试结果。必须72项唯一条件、每项30样本、来源/schema/行一致、连接语义正确、资源样本有限
且非负。历史失败/不完整单列。不从双跳HTTP推断native结果，不混入模型复现费用。相同/
更差/小载荷/schema变更退化如实报告，广泛移植前做设计复核；不改既有alpha/beta/P20及
安全/registry门禁。

## 正式执行前的采集实现细节

`tools/benchmarks/ncp-transfer-runtime.py OUTPUT`要求已提交且干净的源码，构建Release、
记录源码及实际测试程序集哈希，再为每个条件单独调用`dotnet vstest`。去掉不需要的外层
MSBuild进程，仍把全部实际测试平台/testhost后代进程计入内存边界。每10ms读取`/proc`，
同时报告并发RSS观测峰值和各存活进程VmHWM之和的保守上界，两项都必须不超过512MiB。
采样峰值不代表内核连续监控，也不归因于某个协议。冷连接关闭指客户端前端；后台服务端
清理可能与后续调度重叠。每个热连接均先在计时外完整读取一次，再进行三次丢弃预热。
HTTP gzip使用平台GZipStream Fastest，MessagePack使用现有NPS JsonElement格式化器。
原生夹具的只读NWP Action请求使用现有.NET codec；可移植schema-batch响应不代表其他SDK
旧NWP请求映射已获资格。部分成功样本和进程失败均保留在采集目录中。
