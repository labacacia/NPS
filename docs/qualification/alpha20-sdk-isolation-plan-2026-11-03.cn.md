# D20-08 SDK 独立验收

Python、TypeScript、Go、Rust 的部分共享解析测试此前使用私有单体仓库固定相对
路径。本次沿用已有逐级查找 conformance 根目录的方式，继续使用同一组共享夹具
和规范实现。TypeScript 增加现有实验函数的 `/alpha20` 和可选 `/alpha20/sqlite`
公开包入口；导出入口不代表运行时宣告支持，也不等于完成兼容矩阵单元。

先提交源码，再使用已审查的所有权映射和 `tools/release/prepare-sdk-projections.py`
生成六份独立输入。记录源码提交、映射与文件树哈希、工具链、命令、退出码和测试
数量。在独立 SDK 根目录执行原有测试，携带共享 conformance 资产，不依赖私有
单体仓库路径。Python 既有90%覆盖率门槛保持不变。另行构建真实包并验证公开导入，
源码导入不能证明包入口可用。若使用未发布的候选版本覆盖，只能发生在隔离输入，
须绑定源码；规范仓库和包仍为19，等待单独的发布流程。修复前失败结果须保留。

工具回归涵盖隐藏源码/映射改动、路径穿越与通配符、脏工作区、缺失输入、输入/
输出符号链接、禁止覆盖、所有权冲突、可执行权限、依赖锁篡改、缺失发布目录和
六 SDK 字节来源。高风险审查仅限供应链改动，实际验证由主代理执行。工具不发布
或修改既有仓库。独立测试通过不填充576个 native/HTTP 运行时兼容单元、不豁免
旧门槛、不证明发布权限。D20-08 保持 IN_PROGRESS。
